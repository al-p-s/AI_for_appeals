# AI_for_appeals
Система автоматической обработки и классификации обращений граждан в администрацию города по тематическому классификатору Администрации Президента РФ (коды формата `xxxx.xxxx.xxxx.xxxx`).

Пайплайн принимает на вход скан или PDF обращения, распознаёт текст, выполняет многоуровневую классификацию тематики, извлекает реквизитные поля и сущности (NER), после чего формирует готовую XML-карточку для импорта в муниципальную систему электронного документооборота (СЭД).

---

## Ключевой функционал

- **Распознавание текста (OCR)**: поддержка многостраничных PDF и изображений (PNG, JPG, TIFF).
- **Иерархическая классификация (L2 → L3 → L4)**: каскадный многоклассовый выбор категорий официального классификатора Администрации Президента РФ с фильтрацией по порогам уверенности.
- **Определение реквизитных полей**: автоматическое заполнение типа обращения, способа доставки, типа рассмотрения (`первичное` / `повторное` / `неоднократное`) и др.
- **Извлечение сущностей (NER)**: определение ФИО заявителя, почтового адреса, телефона, email и льготной категории через локальную LLM.
- **Экспорт в СЭД**: формирование стандартизированных XML-файлов карточки документа.

---

## Используемые модели и инструменты

- **OCR**:
  - **GLM-OCR** — VLM-пайплайн через локальный LM Studio (приоритетный).
  - **Классический OCR-стек** — Poppler (`pdf2image`), PaddleOCR, Tesseract (резервный / гибридный слой).
- **Классификация тематик и реквизитов**:
  - **KERYX** (L2, L3, L4, реквизитные поля) — дообученные трансформерные NLI/Cross-Encoder модели (PyTorch / CUDA).
- **NER и структурирование данных**:
  - **Qwen** (семейство Qwen2.5 / Qwen3.5) — запуск через локальный OpenAI-совместимый API LM Studio.
- **Сервисный слой**:
  - **Watchdog** — мониторинг горячей папки (`watcher.py`).
  - **FastAPI** — REST API (`api.py`).

## Быстрый старт

### 1. Настройка окружения
Скопируйте шаблон конфигурации и при необходимости переопределите пути:
```bash
cp .env.example .env
```

В `.env` настраиваются:
- Пути к папкам горячей папки (`HOT_DIR`, `INPUT_DIR`, `OUTPUT_DIR` и др.)
- Параметры LM Studio (`LMSTUDIO_BASE_URL`, `LMSTUDIO_OCR_MODEL`, `LMSTUDIO_CHAT_MODEL`)
- Пути к системным утилитам (`POPPLER_PATH`, `TESSERACT_CMD`)
- Пути к лог-файлам

### 2. Режимы работы

- **Сервис горячей папки (основной рабочий режим)**:
  Отслеживает поступление файлов в папку `input`, обрабатывает, сохраняет XML в `output` и переносит исходник в `processed` (или `errors` при сбое):
  ```bash
  python watcher.py
  ```

- **Обработка одиночного документа**:
  ```bash
  python -m src.DEMO.running.run_single path/to/document.pdf
  ```

- **Пакетная обработка и оценка точности (Benchmark)**:
  ```bash
  python -m src.DEMO.running.run_batch
  ```

- **REST API сервис**:
  ```bash
  uvicorn api:app --host 0.0.0.0 --port 8000
  ```
  Интерактивная документация Swagger UI доступна по адресу: `http://127.0.0.1:8000/docs`.

## Структура проекта

```
AI_for_appeals/
├── data/  # Справочники таксономии (cats1-4.json, category_fields.json, XML)
├── models/  # Веса локальных моделей (KERYX L2-L4, реквизитные KERYX)
├── src/  # Исходный код приложения
│   └── DEMO/  # Демонстрационный режим работы
│       ├── functional/  # Классификаторы, извлечение реквизитов, генератор XML
│       ├── loading/  # Загрузчики моделей (KERYX, Qwen)
│       ├── running/  # Скрипты запуска (run_single.py, run_batch.py, app.py)
│       ├── text_extraction/ # Модули OCR (GLM-OCR, Paddle, Tesseract)
│       ├── paths_config.py # Централизованная конфигурация путей
│       └── logger_config.py # Настройка изолированного логирования
├── watcher.py  # Сервис мониторинга горячей папки
├── api.py  # FastAPI сервис
└── .env.example  # Шаблон переменных окружения
```
